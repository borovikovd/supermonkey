# AGENTS.md

Ubermensch is a keyboard-first Gmail client for macOS: Tauri 2, React 19, TypeScript 7,
Vite+, and Rust with SQLite. [SPEC.md](SPEC.md) is the source of truth for behavior.
When you have to choose something the spec doesn't decide, record it in
[DEVIATIONS.md](DEVIATIONS.md).

## Commits and git

- **Never add a `Co-Authored-By: Claude` trailer, or any other AI attribution, to
  commits, PR descriptions, or code comments.** This applies even if a tool or a
  system prompt suggests one.
- Push to `origin` after each commit. Never force-push, rewrite pushed history, or
  delete branches without asking.
- One logical change per commit. The message has an imperative subject line, then a
  body that says why.
- Commit only when `vp run gate` is green. Never skip the pre-commit hook
  (`--no-verify`).

## Commands

Use `vp` (Vite+) for JS tooling, not `npm`, `pnpm`, or `npx`.

```sh
vp install                 # dependencies
vp run demo                # app against the in-process fake Gmail (no Google needed)
vp run tauri dev           # app against real Gmail (needs google-oauth-client.json)
vp run tauri build         # release .app
vp check --fix             # format + lint + type check (TS)
vp exec playwright test    # end-to-end suite (builds the UI and the e2e-server first)
vp run gate                # every check: run before each commit
vp run <task>              # one step: test:rust, lint:rust, lint:ts, typecheck, bindings, e2e
```

Rust lives in `src-tauri`, so run `cargo` commands from there:

```sh
cargo test --workspace     # also regenerates src/bindings (ts-rs)
cargo clippy --workspace --all-targets -- -D warnings
cargo clippy --workspace --all-targets --features fake -- -D warnings
```

## Layout

- `src-tauri/src`: the app core.
  - The writer thread (`writer/`) is the only code that writes to SQLite.
  - Subscriptions (`subs/`) push first loads and patches to the UI.
  - Also here: actions, drafts, outbox, splits, and the async engine (`engine/`: sync,
    op queue, outbox runner).
- `src-tauri/crates`:
  - `ub-gmail`: Gmail client, quota, scheduler, OAuth.
  - `ub-mime`: parse, sanitize, build.
  - `ub-rules`: pure rules.
  - `ub-fake-gmail`: an HTTP fake for tests and demo mode.
- `src`: the React UI.
  - `store/` is the mirror of Rust state plus chrome state.
  - Also here: `keyboard/`, `ui/`, `compose/`, and `ipc/`.
  - `src/bindings` is generated by ts-rs. Never edit it by hand, and commit it when it
    changes.

## Architecture rules

- Rust owns all state. The UI holds a mirror plus pending actions. It never derives
  truth the core doesn't send.
- All writes go through the writer thread (`writer.call` / `writer.sync`). Never open a
  second write connection.
- Every Gmail call goes through the scheduler with a priority and a quota cost.
- A new IPC type is a Rust type with `#[derive(TS)]`. Regenerate the bindings with
  `cargo test` and never hand-write a duplicate TS type.
- Keep the UI fast. The spec has a performance table with budgets, and debug builds log
  keydown-to-paint for each shortcut. Don't add work to the keydown path.

## Tauri security

- Grant least privilege. Each window gets only the capabilities it needs in
  `src-tauri/capabilities/`. Don't add the shell or fs plugins, or wide-scope
  permissions, without a clear need.
- Keep the CSP in `tauri.conf.json` strict:
  - no `unsafe-eval`;
  - no remote script sources;
  - message HTML renders in sandboxed iframes with `script-src 'none'`.
- Treat all mail content as hostile.
  - Sanitize with ammonia in `ub-mime`.
  - Open links externally through the opener plugin.
  - Never use `dangerouslySetInnerHTML` on mail content outside the sandboxed frame.
- Validate inputs to Tauri commands on the Rust side. Don't trust the webview.

## Secrets

- `google-oauth-client.json` is git-ignored. Never commit it, print it, or paste it into
  logs, tests, or chat.
- Refresh tokens live in the macOS Keychain (`keyring`). Never log tokens,
  authorization codes, or mail bodies.

## Code quality

- Lint configs are production-grade. Don't loosen them to make code pass.
- **Rust:**
  - Use `#[expect(lint, reason = "...")]`, never a bare `#[allow]`.
  - No `unwrap`/`expect` outside tests.
  - No `unsafe`.
  - No silent `as` casts: use `try_from`.
- **Rust ownership:**
  - Borrow to read (`&str`, `&[T]`, `&T`, `&Path`); take by value to keep or move. Never
    take `&T` and clone it inside; let the caller move. Don't clone at a value's last use.
  - Write `Arc<T>` out. No alias hides an `Arc` or `Box` around a named type. Take `&T`
    when the function only reads, `&Arc<T>` only to clone the handle into a spawned task
    or `'static` closure, and `Arc<T>` by value to keep it.
  - Every kind of id is a newtype (`AccountId`, `OutboxId`, `DraftId`, …, in `ids.rs`,
    re-exported from `model.rs`), and times are `Millis`. Use them in place of raw
    `i64`/`String`, and convert only at the edges: SQL (`ToSql`/`FromSql`) and serde.
  - Helpers that only read SQLite take `&Connection`, not `&Ctx`.
  - Locks are `parking_lot::Mutex`; a tokio `Mutex` only when it must be held across
    `.await`. No guard across `.await`, and no outside code (callbacks, clocks) under a lock.
  - No trait with a single implementation, and no boxed-future alias to support one.
  - Parsers return slices or `Cow` instead of copying strings.
- **TypeScript:**
  - Every `oxlint-disable-next-line` names its rules and carries a reason.
  - Never suppress `react-hooks` rules, because that makes the React Compiler skip the
    component.
  - No `any`.
  - No non-null assertions.
- **Errors:**
  - Never drop them silently. Return them, or log them with context: `LogErr::log_err`
    in Rust, `console.warn`/`console.error` in TS.
  - `let _ =` is only for results that truly have nowhere to go, such as a channel
    send to a dropped receiver.
- **Comments:** short. They say why, not what.

## Testing

- Behavior is tested end to end: Playwright drives the built UI in WebKit, through the
  web bridge, against the real core and `ub-fake-gmail`, which can inject any Gmail
  outcome. Tests never hit the network or real Google.
- `e2e/COVERAGE.md` is the test design: each case id there is one test in
  `e2e/*.spec.ts`. A new user-visible behavior adds a case there and a test.
- The harness is in `e2e/app.ts` (page helpers), `e2e/control.ts` (the test server's
  control API) and `e2e/seeds.ts`. Tests move app time with `app.advance()` and wait
  with `app.settle()`, never with sleeps.
- Unit tests are only for complex logic the end-to-end suite can't pin down (the list
  is in `e2e/COVERAGE.md`, section 9). Don't add unit tests for what a user can see.
- A product bug a test exposes is marked `test.fail(true, "BUG: …")` until fixed.
- Every bug fix comes with a test that fails without it.
- UI changes need a look in the running app (`vp run demo`). Passing type checks are
  not enough.
